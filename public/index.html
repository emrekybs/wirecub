What it looks for

Detections run on every capture. There is no quick mode that skips checks, so an empty tab means nothing was found, not that nothing was looked at.

Attacks
Port scans, C2 beaconing, DNS tunnelling and DGA domains, SQL injection, XSS, path traversal, RCE and Log4Shell with the payload shown as it arrived, exfiltration, lateral movement, web and reverse shells.
Credentials
Usernames and passwords from FTP, Telnet (line and character mode), POP3, IMAP, SMTP, HTTP Basic and Digest, SMB and SIP. Readable secrets are kept apart from hashes that need cracking.
Windows
NTLMv1, password spraying, one account spreading across hosts, Kerberoasting with the targeted service account named, SMB1, unsigned and null sessions.
Files
Rebuilt from the packets and hashed with MD5, SHA-1, SHA-256 and imphash. Signatures for PowerShell staging, Office macros, ransom notes, shadow copy deletion, packers, credential dumpers and leaked keys.
Ransomware
High-rate writes across file shares, ransom notes and known encrypted-file extensions.
Telephony
SIP calls rebuilt: who called whom, answered or not, duration, codec, packet loss. Unencrypted audio, registration attacks and spoofed INVITEs.
OT, IoT and wireless
Modbus, S7comm, DNP3 and BACnet write commands, controllers reachable from outside, anonymous MQTT, deauthentication floods, evil twins, captured WPA handshakes.
Context
Typosquatted domains, Tor and VPN egress, QUIC with the server name recovered, and sandbox environments, so you know when the outside of a capture was simulated.

Results export as HTML, JSON, STIX 2.1, MISP and CSV. Two captures of the same network can be compared: new hosts, new destinations, findings that appeared and findings that went away.

How a capture is read

The same six steps for every file, in this order.

  1. Open

    pcap and pcapng, plain or compressed with gzip, bzip2 or zstd. Ethernet, Linux cooked, raw IP, VLAN and QinQ, MPLS, GRE, VXLAN and Geneve.

  2. Decode

    Every layer of every packet. IPv4 and IPv6 fragments are put back together before anything reads them.

  3. Rebuild

    TCP streams reassembled in order, retransmissions and overlaps resolved, then HTTP, SMB and SIP sessions reconstructed from them.

  4. Extract

    Files carved out and hashed. Credentials recovered. TLS server names and fingerprints recorded.

  5. Detect

    Detection modules run over the whole result and map what they find to MITRE ATT&CK techniques.

  6. Score

    Findings are ranked by severity and confidence into one risk score and a verdict written as a sentence.

What happens to your capture

Packet captures hold passwords, cookies and private conversations. This site is built to forget them.

The capture is not stored
It is analysed on the server and deleted the moment the analysis ends, whether it succeeds or not.
The report is temporary
The report and any files extracted from the traffic exist only while you read them. They are deleted when you close the page or start a new scan, and automatically after an hour if the page never gets the chance to say so. Downloads you save stay yours.
There is no history
No list of analyses is kept anywhere. Nobody else using WireCub can see what you uploaded, and you cannot see theirs.
No account, no tracking
No sign-up, no cookies, no analytics. Vercel, which hosts the site, keeps its usual short-lived request logs.
Nothing goes to third parties
Only if you switch on live network context in the Reputation tab are the external IP addresses of the capture, and nothing else, sent to ip-api.com to look up their owner and location.

If a capture must not leave your network, run WireCub on your own machine. It is the same program and keeps everything local.
